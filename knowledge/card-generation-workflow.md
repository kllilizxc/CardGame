# 当前可用流程（2026-09-26）

用户已选定由 Codex 内置 imagegen 生成插画。默认不切换到第三方收费 API。卡面组装为确定性代码模板，切换主题复用同一插画。

在 Worka 的“卡牌游戏”桌面：卡牌库选中单位卡 → 制作卡面 → 人工微调/确认 → 复制 Codex 生图任务 → 回填图片 → 组装两套主题 → 加入游戏。也可在 AI 资源生产中新建空卡组工作流，再通过原生会话生成草稿。

卡面主题已有青玉 jade 与宣纸 scroll。`cardFace` 保存当前主题、原画和各主题贴图。完整预览包含基础攻防，游戏贴图不烘焙攻防数字，由实际 CardSprite 绘制战斗实时值。卡牌库可切换默认主题；游戏视图的外观偏好与规则数据分开。

批次拥有 productionId；每张卡沿用 cardId。Codex 回填必须使用当前 requestId；微调使用最新 baseRevision。禁止直接替换已人工确认卡组。AI 生成的新效果需核对可执行结构与 scriptId，不能以文案代替机制。正式资料位置仍是 public/data/cards/units.json，素材在 public/assets/card-faces/。

当前支持单位卡；新卡的掉落、商店、初始牌组仍需配置。以下保留最初的路线调研，3D 与其他卡种尚未实现。

# 卡牌生成工作流

2026-09-26。状态：方案已沉淀，完整自动工作流尚未实现或启用。当前页面是知识库中的制作规范入口，不是可执行的生成按钮。

## 目标与推荐路线

AI 设计一套新卡及可玩套牌 → 人工微调 → 生成素材 → 组装卡面 → 加入候选游戏并试玩。

优先采用 **2D 无字卡图 + 固定卡面模板 + 动态文字/数值**。需要复用角度、角色动作或法器模型的资产，再采用 **概念图 → 3D 模型 → 固定场景渲染**。两条路线最终交付同一种卡图，使用相同的牌面组装与游戏接入流程。

暂按新卡设计加套牌组合理解“生成卡组”；若只是从现有卡池组牌，复用已有定义和素材。像素风沿用既有制作方向，最终风格与尺寸先做小样确定。

## 一次制作如何进行

1. 在原生便笺对话中说明主题、玩法意图和大致规模。AI 读取[卡牌与法器资料](../public/data/docs/cards-artifacts-index.md)、[战斗规则](../public/data/docs/battle-rules.md)、现有卡与实际支持的机制，再生成草稿。
2. 在卡牌库查看定义与差异。少量数值直接编辑，批量调整通过对话完成。说“按这版继续生成素材”后，固定当前输入版本。
3. AI 资源生产按统一参考包制作无字卡图，每张保留有限候选；提供采用建议，用户可否决并说明问题。AI 和工具承担返修及文件整理。
4. 用游戏共享渲染器组装牌面并生成整套联系表。核对中文、长文案、插画裁切和实际显示大小；数值与文字保持可编辑。
5. 执行台把数据、卡组、素材和模板引用交付到同一个候选版本，通过[试玩](./preview.md)验证能找到、抽到、打出卡牌并触发预期行为。

保存文件只更新内容，不自动启动付费生成。首次美术定调建议看一次小样；之后按已确定的批次范围执行，不要求逐卡重复确认。

## 修改与结果必须可追溯

| 修改 | 应发生什么 |
| --- | --- |
| 改攻防或通常的规则数值 | 重新校验、组装和验证，保留仍适用的插画 |
| 改主体形象或风格 | 重做受影响素材和卡面 |
| 改裁切、卡框或排版 | 用原图重新组装 |
| 改套牌数量 | 校验卡组与试玩，复用卡面 |

人工修改形成新版本，AI 后续改动以差异提交；旧生成结果不能覆盖新人工版。素材生成完成、资源采用和进入可玩版本是三个不同事实。已采用批次固定版本，回退同时恢复卡牌数据、卡组和资产引用。

知识库保存规范；卡牌库保存卡牌定义；资源库管理素材及版本；生产便笺保存批次与制作记录；执行台拥有运行事实；试玩拥有体验入口。反馈仍归 Todo。实际目录与持久化边界沿用[工作台说明](./workbench.md)。

## 首个试验批次

建议用 6 张不同定义覆盖：2 单位、1 法器、1 符箓、1 法阵、1 丹药。实际套牌张数按游戏规则另定。

先用占位图验证模板与游戏加载，再做 2D 基线；只给一件法器增加 3D 对照。比较通过验收的卡的总成本、返修次数、选择用时、风格一致性和多角度复用收益。

暂定像素素材优先试 [PixelLab](https://api.pixellab.ai/v2/docs)；插画或概念图可试 [FLUX.2 多参考编辑](https://docs.bfl.ai/flux_2/flux2_image_editing)；3D 对照采用 [Meshy 图生模型](https://docs.meshy.ai/en/api/image-to-3d)与 [Blender 渲染](https://docs.blender.org/manual/en/4.4/advanced/command_line/arguments.html)。这些是已核对官方接口的候选方案，尚未完成本项目效果和成本实测。
