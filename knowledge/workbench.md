# 工作台使用说明

## 内容归属

知识库保存剧情、设定、规范与内容引用。卡牌库编辑现有 JSON；资源库管理文件及版本，使用位置在知识库反向链接中查看。

Todo 保存需求、反馈和验收要求。AI 资源生产保存制作要求、参考版本和候选；所有模型运行由执行台承接。试玩只用于运行和体验游戏。

## 明确交办

保存文件只更新索引。Todo 的交办和制作单的生成按钮才启动工作。同一个制作请求的新轮次复用原执行任务；传输重试复用原请求标识。

素材先登记为未采用候选。单卡制作形成确切 Git 试玩版本；用户在原试玩便笺体验，再到所属功能进展项确认后才进入正式项目。像素美术与 spritesheet 的生产、加工和导出由 AI 完成。

## 写作和版本

普通 Markdown 链接都可阅读导航，只有写作指南声明的场景选项才进入游戏。章节、人物和设定继续用索引页与普通链接组织。

知识库原生对话是资料和剧情改稿入口。先从已登记的 CardGame 内容查询读取目标文档及 `revision`，再从功能进展读取所属 `featureId`。改普通资料时，在知识库会话调用工作台的 `extension.invoke`，使用扩展 `cardgame-content` 的 `stageDocumentsCandidate`，输入 `projectId`、`featureId`、修改说明与带 `expectedRevision` 的文档。改可玩剧情时使用同一扩展的 `stageStoryCandidate`，并提供稳定的 `storyId`、入口文件、场景文档和所需的启动位置。具体字段和条件以项目的[剧情编写指南](../public/data/docs/story-authoring-guide.md)及已登记的扩展契约为准；不要用正式文件保存动作绕过候选。

候选会进入原试玩便笺；实际试玩确切版本后，只在所属功能进展项确认采用或撤销。未确认前正式项目文件不变。外部编辑器修改了目标文件时，重新读取版本并重建候选，不能用旧 `expectedRevision` 覆盖。

新增便笺视图可保存筛选，继续使用同一索引。二进制文件与全文不放进便笺状态或连线载荷。
