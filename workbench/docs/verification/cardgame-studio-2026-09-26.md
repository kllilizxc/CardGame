# CardGame 创作工作流实施与验收（2026-09-26）

依据：[实施交接](../design/cardgame-studio-implementation-handoff.md)。本记录按时间追加实际修改与验证；早期段落描述当时状态，最新试玩状态见下方暂停检查点。历史单卡证据见 [此前记录](card-workflow-2026-09-26.md)。未运行全量测试或发布。

## 本轮实现

- 卡牌库与生产便笺以已有功能进展的稳定 `featureId` 建立制作单。卡牌原始 JSON 的修改保存为草稿；主题选择只影响当前预览。两个便笺从同一桌面的官方功能进展读取功能选择，且官方 tracker 限制跨便笺资源只能读取同桌面的官方记录。
- 制作单保存卡牌定义、素材版本、功能 ID、源 revision 和候选。现有 CR_001 插画可复用；数值改变不要求重新生图，主题模板可重用插画。冻结制作草稿是制作步骤，不记作用户批准。
- 单卡组装在 Worka 数据目录中建立隔离的候选 Git 仓库，记录确切提交、候选 hash、目标基线与文件依赖闭包；自动把候选交给原试玩便笺。CardGame v2 适配器检查入口、内容目录、目标卡定义、两主题贴图及默认可玩卡组。试玩浏览器存档按项目、候选、提交与 profile 命名空间隔离。
- 只有现有功能进展中合格候选的“加入我的游戏”能采用到已登记项目。采用服务按项目串行，检查候选、试玩证据与目标基线，保存恢复日志；重复确认幂等，失败恢复，撤销保护后续外部编辑。确认只处理目标卡、相关贴图与清单及试玩默认卡组的依赖闭包。
- 便笺内容区移除了重复讨论、试玩及采用入口。原生 DSH 会话上下文跟踪便笺、选中对象和 revision，打开选择不先发模型请求。功能进展保留原列表、搜索、筛选、归档、PR/CI/部署结构，只在所属功能项显示候选与采用记录。
- 原生 CardGame 内容会话的文件编辑与命令工具在宿主 `tools/pre-execute` 阶段被拒绝，包括 Bash、Edit、Write、apply_patch 及其常见别名；卡牌修改须通过便笺动作进入候选。守卫沿原生父会话链继承便笺绑定，普通工程会话不受此 CardGame 限制。
