# 卡牌工作流与主题系统验收

用户要求：将已验证的单卡制作流程接入 Worka，后续由 Codex 生图；同一张卡能够切换不同模板。

## 实际交付

- 原有卡牌库增加“制作卡面”，沿用卡牌 ID、原始 JSON 与 revision；制作便笺增加五阶段工作流。仍可继续原有普通素材制作请求。
- 工作流复用 production 存储、历史和 CAS；候选图复用 content 资源版本库。卡牌草稿、人工确认、插画、生图请求、裁切/主题、组装、入库分别保存。
- 插画通过 Codex 生图任务及对应请求回填。当前不是 Worka 远程自动调用 Codex 图像工具。原生便笺 AI 会话可生成结构化草稿；本轮没有触发该模型运行。
- 青玉与宣纸是两套布局。组装得到完整预览和无固定攻防数字的游戏贴图；CardSprite 继续使用真实战斗数值、境界和原有功法提示。卡面偏好不写入战斗状态。
- 首期支持单位卡。新卡进入 units.json，不自动编造掉落、商店、初始牌组或新增机制。

## 已验证

- Worka 类型检查、受影响便笺类型检查、构建和打包通过。包中包含工作流/模板源文件，没有包含本机 connection.json 或 .workbench 数据。
- 首轮四个相关测试文件 36 项通过：新增卡牌工作流、原有制作交付、工作流存储、卡牌库。后续只重跑直接受修改影响的集合；最终卡牌流程 4 项通过。没有运行全量测试。
- 新回归覆盖人工确认、真实 PNG 生成/采用、两套主题、模板切换复用插画、旧回执、版本冲突、源文件并发修改、新卡 ID 冲突、重复采用和重启恢复。
- CardGame 针对预览链路的类型检查通过；卡面加载/偏好 2 项测试覆盖异步旧结果、取消订阅、缺失与非法贴图回退。
- 在正在运行的 Worka 中更新卡牌库与制作便笺，复用已确认的青云山灵狐插画完成回填、组装、入库。之后重启验证数据仍在，7 个既有便笺及 14 条显式关联有效。
- 实际浏览器检查制作便笺 compact/expanded、深浅主题及 390px 窄屏。窄屏 iframe 宽 390、文档宽 375，无横向溢出。主题由青玉切到宣纸后，预览与“待加入游戏”状态同步变化；点击加入游戏后变为“已加入游戏”。最终示例恢复青玉默认主题。
- 实际游戏 CardSprite 加载宣纸贴图（HTTP 200），按钮触发实时攻击与生命更新；既有试作页改为读取最新采用数据，消除 Vite 公共 JSON 模块旧缓存影响。
- 对比入库前后的单位卡 JSON：17 张单位卡数量不变，只有 CR_001 新增 cardFace 字段，其数值、效果及其他单位卡均未改变。

## 验证边界

本轮没有再次生图或调用第三方生成 API，没有对真实模型的卡组草稿生成进行端到端验收；没有进行完整战斗、跨平台字体、所有单位功法提示或其他卡种验收。浏览器文件上传入口存在，样卡回填通过相同后端命令完成；文件选择器本身未单独测试。未做全量测试或发布远程版本。中文导出已在本机显式配置 CJK 字体，其他宿主需要相应字体。

截图与本机安装备份保存在忽略的验证目录和任务附件目录，未纳入公共发布包。
