# 卡匣问心：正式游戏接入

运行入口仍是 `src/main.tsx → GameApp → game/main.ts`。启动 `bun run dev-nolog`，访问 `http://localhost:8080/`。原型保留在 `/wenxin-v5/index.html`。

## 已接入

- Preloader 预载统一素材；主菜单使用卡匣，地图、据点、剧情共用像素背景与灰绿、旧金面板。
- 全部卡牌入口经 `watchCardFace` 使用统一卡框与真实卡名。单位攻防及功法交互继续来自 CardSprite。用户明确选过的其他卡面仍保留。
- 17 张单位牌按内容身份映射到弟子、长老、灵狐、幼鹰、玄冰龟、烈焰狼六类造型。人族按角色类型共用立绘；新卡没有映射时保留卡牌形态。
- 符箓与剑类使用原型绘画；其他法器、丹药、场地、功法使用对应类型符印及统一画框，不把法杖误画成飞剑。
- BattleScene 使用原型 640×360 的透视公式、左右三槽与场景摄像机，在 1920×1080 游戏中按 3 倍呈现。立绘脚点固定，逐角色持续 Idle。
- 真实拖拽召唤、近战突进、鹰类升空俯冲、剑修落剑、受击及退场接入现有战斗事件。伤害通过原回调结算，运镜只移动场景与立绘；手牌与 HUD 不随场景镜头位移。
- 剧情使用两侧立绘、中央选择、底部正文；眨眼与表情只修改面部，身体定位固定。既有剧情图、分支、任务、奖励与存档继续由原系统管理。
- 在原型动画时长下，相邻普通攻击间隔使用 1000ms，使升空和返回演出有时间结束。游戏数值与规则数据未作本次修改。

## 文件与素材来源

`materials.js` 是原型素材适配器的 ES 模块版，不包含原型自动战斗脚本。正式游戏的素材独立位于 `public/assets/wenxin/`，不依赖演示页面。

卡框来自已确认原型的 Canvas 原生输出。原系列提示词在 `public/assets/wenxin/series-prompts.json`。新增玄冰龟与烈焰狼使用 **内置 imagegen**、以已确认弟子图为参考生成；完整提示词分别为 `series-turtle-prompt.json`、`series-wolf-prompt.json`。原始生成结果保留，项目中使用其副本。位图纹理统一使用 NEAREST，不把正文文字全局像素化。

并行本地预览曾覆盖同一份 Vite React 依赖缓存，导致正式入口空白。开发缓存现按端口隔离在 `.vite/dev-<port>`。

## 验证

- `bun run build-nolog` 通过。
- `bun test` 与接入前对照：原有两项 content catalog 断言、一项 mapTraversal 断言仍失败；本次没有新增失败。
- 新增纯测试检查所有正式单位的素材映射、镜像站位与原型投影。
- 浏览器用隔离存档实测：菜单 → 大地图 → 青云宗山门 → 剧情少女分支 → 拖拽召唤 → 回合攻击胜利 → `sect_entry_005_trial_victory`，无运行报错。
- 六类角色均通过间隔像素读回检查：画面变化、根坐标固定。近战、升空、落剑的伤害回调各执行一次；群攻三个目标各执行一次，结束后 pending=0、camera=(0,0)。
- 立绘鼠标命中、单位中途销毁、场景 shutdown 与直接 destroy 的动态纹理清理已检查。
- 实机结果与截图见 `art-references/wenxin-integration/`。
- `tools/wenxin-materials/game-smoke.ts` 是浏览器手动验收夹具，不被正式入口引用，不写存档。

全仓 `tsc --noEmit` 仍有既有类型错误（包括 TurnManagerContext、数据类型和测试使用的 ES 新 API）；新增素材模块无类型诊断。构建脚本与全仓类型检查的结果分别记录，未把构建成功当成全仓类型通过。
